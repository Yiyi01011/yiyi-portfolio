# 贺丹 AI Product Manager 个人作品集｜整站视觉与交互设计规范

> 文档用途：指导个人作品集网站的整站视觉设计、页面结构、交互动效、素材生成与前端实现。  
> 适用范围：首页、项目列表、项目详情、经历、关于我、联系、简历入口、404 与移动端。  
> 主要浏览场景：PC Web 优先，同时适配平板和手机。  
> 参考网站：[Seth Lukin Portfolio](https://sethlukin.com/)。学习其视觉机制、信息节奏和案例叙事，不复制其品牌、配色、文案或具体画面。  
> 最终首页视觉参考：`docs/references/homepage-reference-final.png`。  
> 唯一人物母版：`public/portfolio/avatar/avatar-master.png`。

## 0. 文档定位与最高原则

这不是一份“首页效果图说明”，而是一套整站 Design System 与 Art Direction。首页负责建立第一印象，项目详情负责证明产品能力，经历与关于我负责补全职业可信度，联系区负责完成求职转化。所有页面必须属于同一个低饱和像素世界，并使用同一套排版、色彩、组件和动效语言。

整站遵循以下优先级：

1. **先让内容被快速理解，再提供视觉探索。**
2. **70% 用于项目与经历阅读，30% 用于像素世界和互动趣味。**
3. **功能 UI 清晰现代，视觉插画具有明确像素感。**
4. **页面动效帮助理解层级和方向，不延迟阅读。**
5. **所有关键文字、按钮、导航和项目卡都由真实 DOM 构成。**
6. **整站可以有游戏氛围，但不能要求招聘方学习游戏操作。**

招聘方进入网站后，应在 5 秒内知道：

- 这是贺丹的个人作品集；
- 目标方向是 AI Product Manager；
- 她有设计背景、Agent 产品经验和产品实现能力；
- 可以直接查看项目或下载简历。

## 1. 整个网站要表达什么

### 1.1 核心身份

- 姓名：贺丹
- 岗位方向：AI Product Manager / AI 产品经理 / 产品助理
- 专业特征：设计背景、用户洞察、产品定义、Agent 设计、Vibe Coding、原型与交付
- 工作方式：把模糊问题整理成清晰的产品结构，再推动原型、实现、测试和迭代

### 1.2 核心价值主张

整站核心文案固定为：

> 用设计理解用户，用 AI 构建可落地的产品。

这句话需要被项目内容证明，而不是只作为口号。整站应持续呈现以下证据：

- 能从真实用户问题出发，不先堆功能；
- 能在用户、业务和技术之间做产品判断；
- 能设计 Agent 的任务流程、交互机制和知识结构；
- 能用 AI 与代码快速完成可体验版本；
- 能通过用户反馈、测评和数据继续迭代；
- 有真实项目结果，包括定制化交付与商业结果。

### 1.3 希望形成的第一印象

- 有产品判断
- 有设计能力
- 理解 AI Agent
- 能推进产品实现
- 能清楚讲述过程与结果
- 有个人辨识度
- 认真、清晰、有行动力

不应只留下“会画画”“页面很可爱”或“会使用生成工具”的印象。

### 1.4 整站叙事主线

网站的叙事顺序是：

```text
认识贺丹
→ 看见她的核心项目
→ 理解她如何发现问题与做出决策
→ 看见产品如何实现和验证
→ 补充经历与能力
→ 下载简历或建立联系
```

像素世界是这条主线的空间外壳，项目证据才是主体。

## 2. 页面给谁看

### 2.1 招聘 HR

HR 需要快速判断岗位匹配度、经历、项目数量、简历和联系方式。因此：

- 姓名、岗位、项目入口和简历按钮必须直接可见；
- 首页不能依赖复杂操作才能打开项目；
- 项目卡需要一句话说清问题与结果；
- 联系方式需要在导航、页尾或联系区容易找到。

### 2.2 产品负责人或业务负责人

他们主要判断：

- 为什么做这个产品；
- 用户问题与业务机会是什么；
- 贺丹做出了哪些关键决策；
- 她具体负责什么；
- 产品有没有完成原型、开发、测试或上线；
- 结果与复盘是否可信。

项目详情页必须优先展示决策链路和证据，不能变成图片画廊。

### 2.3 AI、设计与研发协作者

他们可能关注 Agent 工作流、知识库、接口、鉴权、部署、设计系统和跨团队协作。技术内容需要具体，但首页不堆砌技术名词，详细内容放在项目详情页相应章节。

### 2.4 阅读场景

- PC 是主要展示端；
- 招聘方可能只浏览几十秒；
- 用户可能从简历链接直接进入某个项目详情；
- 手机端可能用于临时预览；
- 每个页面都要允许快速扫描，也允许继续深入。

## 3. 参考网站要学什么

参考范围包括 [Seth Lukin 首页](https://sethlukin.com/) 及其案例页面，例如 [Luuna](https://sethlukin.com/case-studies/luuna)、[Twinby](https://sethlukin.com/case-studies/twinby) 和 [ADC Space](https://sethlukin.com/case-studies/adc-space)。

### 3.1 学习强身份首屏

- 用姓名和职业定位建立第一视觉层级；
- 使用大字号、清晰留白和强对比排版；
- 把个人身份、能力方向和作品入口组织为一个完整画面；
- 首屏不是常规 SaaS 落地页，也不是模板化居中 Hero。

### 3.2 学习整页视觉连续性

- 首页、项目索引、案例页和联系区共享同一套视觉语言；
- 项目不是孤立卡片，而是整站叙事的一部分；
- 页面从身份介绍自然过渡到项目、能力和联系；
- 大标题、图像、留白和小型元信息共同建立节奏。

### 3.3 学习案例页的编辑式叙事

- 案例页先给出项目命题、概览、职责和结果；
- 再按问题、研究、判断、方案、验证、反思展开；
- 大图与短段文字交替，避免整页密集长文；
- 每个章节只回答一个清楚的问题；
- 页尾继续提供下一个项目或联系入口。

### 3.4 学习动效与排版的结合

- 动效发生在标题、图片、章节进入和页面过渡中；
- 元素运动与滚动方向一致；
- 页面通过尺度、遮罩、位移和层级变化建立空间感；
- 动效不会让按钮变得难找，也不会改变内容顺序。

### 3.5 学习全站反复出现的联系入口

- 用户从首页、案例页和页尾都能建立联系；
- 项目详情页不形成浏览死路；
- 返回、下一个项目、简历和联系方式始终有明确路径。

### 3.6 参考链接与使用边界（2026-08-15 冻结）

主要交互参考为 [Seth Lukin 首页](https://sethlukin.com/) 及其公开案例页：[Luuna](https://sethlukin.com/case-studies/luuna)、[Twinby](https://sethlukin.com/case-studies/twinby)、[ADC Space](https://sethlukin.com/case-studies/adc-space)。详细分析见 `docs/reference-analysis.md`。

仅借鉴：首页身份进入顺序、自然滚动叙事、项目入口的整体出现、轻量悬停、短页面转场、案例页图文交替和页尾继续行动。

不得复制：品牌、姓名与文案、项目内容和数据、图片、具体版式、字体组合、按钮造型、遮罩形状、联系布局和写实视觉风格。参考站不作为生成图片的直接输入。

参考站只影响交互节奏和内容容器，不改变首页 P0 的 10 项素材拆分、PNG 母版格式、尺寸、锚点、安全区域、z-index 或手机策略。若参考站与本规范或首页最终参考图冲突，以本规范和 `docs/references/homepage-reference-final.png` 为准。

## 4. 参考网站不要学什么

### 4.1 不复制黑白高对比风格

本网站使用暖白和低饱和马卡龙色，不复制参考站的黑白视觉、字体组合或具体构图。

### 4.2 不复制过低的信息密度

AI 产品经理作品集需要更早展示：

- 产品解决的问题；
- 我的角色；
- 关键决策；
- 实现状态；
- 结果与数据。

### 4.3 不复制具体品牌资产

不得复制参考网站中的姓名排版、项目图、文案、交互图标、按钮造型和联系信息布局。需要形成原创的“贺丹 AI 产品世界”。

### 4.4 不让动效压过内容

- 不设置长时间开场动画；
- 不使用全屏 Loading 阻挡正文；
- 不劫持滚轮；
- 不要求拖拽、控制人物或完成任务后才能看项目；
- 不让标题跟随鼠标逃离；
- 不让每个元素同时运动。

### 4.5 不把整张视觉稿当作网页底图

视觉参考只用于构图、比例、配色与氛围。姓名、正文、导航、按钮、项目卡、数据和链接都必须使用真实网页元素。人物、环境、植物和项目插画可以作为独立素材接入。

## 5. 整站视觉概念

### 5.1 核心概念：可探索的 AI 产品世界

整站被理解为一个由浮岛、路径、植物和项目场景组成的个人世界：

- 首页是世界入口；
- 三个核心项目是三个具有不同色彩和隐喻的区域；
- 经历是连接各个区域的路径；
- 能力是散布在路径上的信息标记；
- 关于我是人物档案；
- 联系区是旅程终点，也是下一次沟通的入口。

这个概念只用于建立视觉连续性，不需要实现真实地图或复杂游戏系统。

### 5.2 视觉关键词

- 暖白
- 低饱和马卡龙
- 二维像素画
- 纪念碑谷式抽象体块
- 轻农场与轻探索感
- 清晰现代产品 UI
- 编辑式大标题
- 大面积留白
- 温和、有个性、不过度幼态

### 5.3 视觉比例

- 约 70%：项目内容、真实界面、说明、数据和职责；
- 约 20%：像素环境、浮岛、植物和项目场景；
- 约 10%：人物 IP、气泡和微互动。

### 5.4 功能层与世界层

整站分为两套互相配合的视觉层：

| 层级 | 内容 | 表现方式 |
|---|---|---|
| 功能层 | 导航、标题、正文、按钮、标签、项目卡容器、数据 | 清晰现代、真实 DOM、精确排版 |
| 世界层 | 人物、云朵、浮岛、植物、建筑、瀑布、项目插画 | 二维像素、低饱和、阶梯硬边、有限色阶 |

功能层不能添加低清滤镜。世界层不能变成写实 3D 或高对比游戏贴图。

## 6. 整站信息架构与页面类型

### 6.1 主导航

中文版：

```text
关于我 / 项目 / 经历 / 联系
```

英文版：

```text
About / Projects / Experience / Contact
```

导航左侧固定为：

```text
[HD 圆形头像] 个人作品集
```

右侧可以保留小型像素盆栽作为装饰，不承担核心功能。

### 6.2 页面与路由建议

| 页面 | 建议路由 | 主要目标 |
|---|---|---|
| 首页 | `/` | 建立身份、预览项目、引导继续阅读 |
| 项目列表 | `/projects` | 快速比较三个核心项目 |
| DesignSpark | `/projects/designspark` | 展示设计学生创意引导 Agent 的完整案例 |
| 交换人生 | `/projects/life-exchange` | 展示视角转换机制与情感产品设计 |
| AI 销售 Agent | `/projects/ai-sales-agent` | 展示多智能体销售场景与商业结果 |
| 经历 | `/experience` | 呈现实习、教学、Vibe Coding 与项目经历 |
| 关于我 | `/about` | 解释从环境设计到 AI 产品的职业转向 |
| 联系 | `/contact` | 邮箱、GitHub、简历与沟通邀请 |
| 404 | `*` | 使用轻量像素场景引导返回 |

首页可以包含项目、经历、关于我和联系的摘要；独立页面提供完整阅读，不强制所有内容塞入单页。

### 6.3 全站公共框架

每个页面至少包含：

1. 全局导航；
2. 页面标题或项目标题；
3. 清晰的正文阅读区域；
4. 返回或继续浏览入口；
5. 页尾联系区；
6. 移动端菜单；
7. 键盘焦点与减少动态模式。

## 7. 网格、尺寸与空间规则

### 7.1 页面容器

- 最大内容宽度：`1440px`；
- 正文阅读宽度：`680—780px`；
- 大图最大宽度：`1200—1440px`；
- PC 使用 12 列网格；
- 平板使用 8 列网格；
- 手机使用 4 列网格。

### 7.2 页面边距

| 视口 | 左右边距 |
|---|---|
| ≥ 1440px | 80—112px |
| 1024—1439px | 48—72px |
| 768—1023px | 32—48px |
| < 768px | 20—24px |

### 7.3 垂直节奏

- 页面章节之间：96—160px；
- 项目详情大章节之间：120—200px；
- 标题与摘要：24—40px；
- 摘要与正文：40—64px；
- 正文段落：16—24px；
- 图片与说明：16—28px。

整站应有明显呼吸空间，但不能用巨大空白掩盖内容不足。

### 7.4 圆角与边框

- 小控件圆角：8—12px；
- 项目卡圆角：18—24px；
- 大型媒体容器圆角：20—32px；
- 边框：1px 低对比暖灰；
- 像素气泡与像素装饰允许使用硬边，不套用圆角系统。

### 8.1 全局基础色

| Token | 用途 | 色值 |
|---|---|---|
| `--bg-primary` | 页面主背景 | `#F7F1E7` |
| `--bg-secondary` | 次级背景 | `#EFE7DA` |
| `--surface` | 卡片与媒体底 | `#FBF7F0` |
| `--text-primary` | 标题与正文主色 | `#23252A` |
| `--text-secondary` | 次级说明 | `#68655F` |
| `--border` | 低对比边框 | `#D8D0C4` |
| `--accent-primary` | 主按钮与关键状态 | `#66724E` |
| `--accent-soft` | 浅绿色背景 | `#DCE2C9` |
| `--sky-soft` | 远景天空 | `#BAD7E6` |

### 8.2 项目主题色

| 项目 | 主色 | 辅助色 | 场景隐喻 |
|---|---|---|---|
| DesignSpark | `#98A978` | `#E6E3C9` | 灵感花园、火花、知识地图 |
| 交换人生 | `#E7B39D` | `#F4D8C8` | 双人桥梁、记忆树、信件与时间 |
| AI 销售 Agent | `#B9C2E4` | `#DCE2F2` | 对话节点、机器人、销售路径、仓储空间 |

### 8.3 使用规则

- 暖白与米白占整站约 60%—70%；
- 炭黑负责文字清晰度；
- 主按钮优先使用深鼠尾草绿；
- 项目主题色用于章节背景、编号、图形和局部强调；
- 单个页面同时出现的主要强调色不超过两种；
- 不使用大面积高饱和蓝紫渐变；
- 不使用纯黑作为整站主要背景；
- 项目详情可以有主题色变化，但导航、正文与基础组件保持一致。

### 8.4 人物与环境色彩关系

人物直接使用确认的 `avatar-master.png`，不通过生成模型改色。蓝色帽子、蓝色外套、黑色头发、深色裤子与浅色鞋均以母版为准。环境通过暖白、浅绿、米色和柔桃色与人物融合，不再次改变人物色相。

## 9. 字体与排版系统

### 9.1 字体气质

- 大标题：粗、直接、现代、有编辑感；
- 中文正文：清晰、克制、易扫描；
- 英文岗位与项目名：几何无衬线；
- 数据：紧凑、有产品报告感；
- 像素字体：只用于气泡、小编号或装饰标签。

### 9.2 字体建议

中文优先选择：

- 思源黑体 / Noto Sans SC；
- 阿里巴巴普惠体；
- HarmonyOS Sans SC。

英文优先选择：

- Geist Sans；
- Inter；
- Manrope。

全站最多使用两套主字体。像素字体仅作为第三套装饰字体，并严格限制使用范围。

### 9.3 字号层级

| Token | PC | 移动端 | 用途 |
|---|---:|---:|---|
| `display-name` | 54—68px | 40—50px | 首页“贺丹” |
| `display-role` | 42—54px | 30—40px | “AI Product Manager” |
| `display-page` | 64—104px | 42—64px | 项目列表与页面章节大标题 |
| `h1-case` | 56—88px | 40—58px | 项目详情主标题 |
| `h2` | 36—52px | 28—38px | 大章节标题 |
| `h3` | 24—32px | 22—28px | 子章节标题 |
| `body-lg` | 20—24px | 18—21px | 摘要与引导文字 |
| `body` | 16—18px | 15—17px | 正文 |
| `caption` | 12—14px | 12—13px | 图注与元信息 |

### 9.4 首页标题固定规则

第一行：

```text
贺 丹
```

第二行：

```text
AI Product Manager
```

- 两行左对齐；
- 标题组位于首屏左侧偏上区域；
- “贺丹”两个字之间使用 `0.16em—0.24em` 字距；
- 英文岗位使用 `0.02em—0.045em` 字距；
- 两行之间保留 24—34px；
- 英文岗位与价值主张之间保留 42—58px；
- 英文岗位宽度可以接近价值主张，不强制完全齐平；
- 不使用全大写 `AI PRODUCT MANAGER`。

### 9.5 中文版与英文版

中文版以中文为主，但首页岗位名称固定保留 `AI Product Manager`。产品正式名称、AI、Agent 和 Vibe Coding 可以保留英文。导航、按钮、正文和气泡使用中文。

英文版独立维护文案与换行，不通过直接替换字符串强行共用同一宽度。

## 10. 像素视觉与素材系统

### 10.1 像素强度

- 人物、云朵、浮岛、植物、建筑、瀑布、电脑、路牌与项目插画需要看见方形像素块和阶梯轮廓；
- 像素感只比柔和插画增强一个层级；
- 不提高整体饱和度；
- 不使用深色粗描边覆盖所有素材；
- 不使用统一低分辨率滤镜处理整页；
- 不使用 3D 公仔式光影。

### 10.2 人物母版

固定文件：

```text
public/portfolio/avatar/avatar-master.png
```

该文件是唯一身份母版。清除棋盘格并保存为真实透明 PNG 后，只允许：

- 等比缩放；
- 调整页面位置；
- 透明背景处理；
- 为不同屏幕输出合适尺寸。

不得改变：

- 蓝色鸭舌帽与黄、粉装饰；
- 黑色长发与刘海；
- 棕色眼睛；
- 蓝色外套、黑色内搭、深色工装裤；
- 浅色绿条纹运动鞋；
- 项圈与耳饰；
- 双手交叉姿势；
- 脸型、头身比例和像素块结构。

首屏直接使用母版，不使用“相似人物”或重新生成版本。

### 10.3 人物出现频率

- 首页：完整人物，承担个人识别；
- 项目列表：可以使用小尺寸人物或指向动作，但不是必须；
- 项目详情：只在章节提示、页尾或小型注释中出现，不抢项目界面；
- 经历与关于我：可以出现人物小图或像素头像；
- 联系页：可以使用挥手版本；
- 同一屏幕不出现多个大尺寸人物。

第一阶段不生成新动作。后续动作只有在交互需求明确时制作，并逐项核对人物身份与服装细节。

### 10.4 环境素材模块

环境素材应拆成可复用层：

```text
远景云层
中景浮岛与建筑
主内容平台
前景植物与路牌
项目主题装饰
过渡遮罩
```

每层使用透明 PNG 或 WebP，不生成一张覆盖整页的大底图。

### 10.5 图标

- 功能图标优先 SVG；
- 像素装饰图标使用透明 PNG/WebP；
- 同一组功能图标保持线宽、尺寸与圆角一致；
- 不混用多套默认图标库风格。

数据使用大数字、小说明和真实口径，不使用无证据的百分比。

### 12.6 首页经历区

## 14. 项目详情页设计规范

### 14.1 项目详情页目标

项目详情不是作品图片集合，而是产品决策记录。每个项目都要回答：

```text
问题是什么
→ 为什么值得解决
→ 我负责什么
→ 做了哪些判断
→ 产品如何工作
→ 如何实现与验证
→ 得到了什么结果
→ 下一步如何改进
```

### 14.2 固定章节模板

1. **项目 Hero**：项目名、命题、主题场景、时间、角色、状态；
2. **Overview**：背景、用户、问题、目标；
3. **My Role**：职责、协作对象、交付范围；
4. **Challenge**：核心挑战与约束；
5. **Research / Evidence**：调研、访谈、竞品、数据；
6. **Key Insights**：重要发现；
7. **Product Strategy**：范围、优先级、关键决策；
8. **Core Flow**：核心流程或 Agent 工作流；
9. **Solution**：关键页面、交互和功能；
10. **Implementation**：技术方案、协作与上线；
11. **Validation**：测试、评估、迭代；
12. **Results**：结果、数据、交付状态；
13. **Reflection**：复盘与下一步；
14. **Next Project**：下一个项目入口。

不要求三个项目机械使用相同章节数量，但必须保持“问题—判断—方案—结果”的主线。

### 14.3 项目 Hero

- 使用项目主题色；
- 主标题清楚说明项目命题，不只写产品名；
- 右侧或下方放项目场景图；
- 首屏同时显示项目名、我的角色、时间和状态；
- 提供“返回项目”入口；
- 不重复首页的大人物构图。

### 14.4 项目元信息

建议以 3—5 列信息带呈现：

```text
角色 / 时间 / 团队 / 平台 / 状态
```

移动端改为两列或纵向排列。

### 14.5 正文与图片节奏

- 每个大章节先给结论，再给过程；
- 单段正文控制在 3—6 行；
- 大图、双列图、流程图和文字段落交替；
- 图像必须有图注，说明它证明什么；
- 界面图使用真实产品截图或高质量原型；
- 装饰场景只用于章节过渡，不覆盖核心界面。

### 14.6 章节导航

PC 可使用左侧或顶部轻量章节进度：

- 显示当前章节；
- 点击可跳转；
- 不遮挡正文；
- 手机端改为折叠目录或仅保留返回按钮。

### 14.7 流程图与技术内容

- 流程图使用清晰 SVG 或真实 DOM；
- Agent、RAG、API、鉴权和日志使用通用产品语言解释；
- 先说明它解决什么问题，再说明技术结构；
- 不使用密集代码截图作为主要证据。

### 14.8 项目页尾

必须包含：

- 项目结果摘要；
- 反思；
- 上一个 / 下一个项目；
- 返回项目列表；
- 联系入口。

## 16. 整站动效语言

### 16.1 动效目标

动效需要完成以下任务：

- 提示页面层级；
- 表达滚动方向；
- 连接不同场景；
- 强化按钮与卡片反馈；
- 让像素世界有轻微生命感；
- 保持内容阅读连续。

### 16.2 动效等级

#### 一级：必须实现

- 页面进入与退出；
- 导航当前状态；
- 按钮悬停、点击和键盘聚焦；
- 项目卡进入视口；
- 项目详情章节进入；
- 锚点跳转；
- `prefers-reduced-motion` 降级。

#### 二级：建议实现

- 云朵、浮岛和前景植物轻微视差；
- 项目图片遮罩展开；
- 数字与结果在进入视口时出现；
- 项目卡主题色过渡；
- 首页人物首次进入时轻微上浮；
- 页面底部到下一项目的连续过渡。

#### 三级：后续评估

- 人物挥手或指向动作；
- 人物根据章节改变小动作；
- 项目场景更复杂的多层视差；
- Canvas 或 WebGL 场景。

第一阶段不制作人物走路系统，也不引入 Three.js。

### 16.3 时间与缓动

| 动效 | 时间 | 建议缓动 |
|---|---:|---|
| 按钮与小控件 | 140—220ms | `ease-out` |
| 卡片悬停 | 220—320ms | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| 内容进入 | 420—650ms | `cubic-bezier(0.22, 1, 0.36, 1)` |
| 图片遮罩 | 550—800ms | `cubic-bezier(0.65, 0, 0.35, 1)` |
| 页面过渡 | 550—850ms | `cubic-bezier(0.76, 0, 0.24, 1)` |
| 场景视差 | 跟随滚动 | 线性映射 |

### 16.4 位移范围

- 小控件：2—8px；
- 卡片与内容进入：12—32px；
- 大标题：20—48px；
- 场景层视差：总位移 8—40px；
- 人物待机上下移动：不超过 4—6px。

### 16.5 首页进入动效

顺序建议：

1. 导航淡入；
2. “贺丹”由下向上进入；
3. “AI Product Manager”稍后进入；
4. 价值主张与按钮出现；
5. 人物与中央浮岛轻微上浮；
6. 对话框最后出现；
7. 两侧环境做轻微位移。

总时长控制在 1—1.3 秒，0.4 秒内先显示可阅读文字。不要逐字播放完整标题。

### 16.6 滚动动效

- 保留浏览器自然纵向滚动；
- 不使用滚动锁；
- 不改变滚动方向；
- 章节进入使用淡入、上移和遮罩；
- 背景层移动速度低于内容层；
- 前景植物速度略高于内容层；
- 快速滚动时内容仍完整出现；
- 项目详情正文不使用每一行逐字显现。

### 16.7 页面转场

#### 首页 → 项目详情

- 点击卡片后，项目主题色或封面图进行短暂扩展；
- 页面内容淡出并上移；
- 新页面 Hero 从同一方向进入；
- 转场不超过 850ms；
- 浏览器返回后恢复原滚动位置。

#### 项目详情 → 下一个项目

- 页尾显示下一个项目的主题色、名称和局部场景；
- 点击后沿滚动方向进入；
- 不使用黑屏或长时间 Loading。

#### 普通页面转场

- 导航与背景可以保持；
- 主内容使用 12—24px 位移与透明度变化；
- 不为每个页面设计完全不同的转场。

### 16.8 像素环境待机动效

- 云朵：12—20 秒缓慢水平移动；
- 浮岛：10—16 秒、4—6px 上下移动；
- 植物：8—14 秒轻微摆动；
- 瀑布：可以使用小型循环序列，但需控制资源体积；
- 电脑屏幕：低频闪烁，不持续高亮；
- 同一屏幕最多 2—3 组持续动画。

### 16.9 减少动态模式

当用户开启 `prefers-reduced-motion`：

- 关闭视差；
- 关闭持续漂浮；
- 页面转场改为快速淡入淡出；
- 内容直接出现；
- 保留按钮状态与焦点反馈；
- 不影响任何信息和功能。

## 17. 响应式规则

### 17.2 平板：768—1199px

- 减少两侧浮岛；
- 项目卡改为两列或横向大卡；
- 人物缩小；
- 项目详情大图保持单列；
- 章节导航改为顶部或折叠形式；
- 降低视差位移。

### 17.3 手机：< 768px

- 内容改为单列；
- 标题保持两行左对齐；
- 人物放在标题与按钮下方；
- 两个按钮可以并排或纵向排列；
- 项目卡单列；
- 移除两侧复杂装饰；
- 关闭自定义鼠标和复杂视差；
- 项目正文宽度占满可用区域；
- 图片可以横向滚动时必须有明确提示，否则使用纵向排列。

### 17.4 文案长度适配

- 中文和英文分别维护；
- 不通过缩小到难读字号解决溢出；
- `AI Product Manager` 不能在 `Product Manager` 中间出现不合理断行；
- 项目标题过长时优先调整行宽和换行点；
- 按钮保持至少 44px 点击高度。

## 18. 可访问性与性能

### 18.1 可访问性

- 所有按钮、链接与卡片支持键盘操作；
- 焦点状态可见；
- 装饰图片使用空 `alt`；
- 项目图使用描述性 `alt`；
- 颜色不是表达状态的唯一方式；
- 不自动播放声音；
- 正文保持足够字号与行距；
- 气泡内容不承载唯一信息；
- 页面标题层级符合 `h1 → h2 → h3`。

### 18.2 性能

- 首屏优先加载姓名、岗位、价值主张和按钮；
- 图片声明宽高，避免布局跳动；
- 非首屏图片延迟加载；
- 大面积插画优先 WebP；
- 透明人物保留 PNG；
- 按实际展示尺寸输出图片，不直接加载超大母版；
- 动画优先使用 `transform` 和 `opacity`；
- 避免持续改变大面积模糊、阴影和滤镜；
- 同一页面不运行多个 Canvas；
- 页面不可出现双滚动条；
- 页面不可因为装饰动画产生明显卡顿。

## 19. 不要出现的常见 AI 网站风格

### 19.1 不使用蓝紫霓虹科技背景

避免深蓝背景、蓝紫渐变、发光网格、赛博空间、数据流和发光大脑。

### 19.2 不滥用玻璃拟态

避免全部卡片半透明、大面积背景模糊、透明胶囊按钮、多层发光边框。

### 19.3 不使用默认 AI 图标语言

避免四角星、魔法棒、宇宙、通用机器人、神经网络大脑和没有功能的聊天气泡反复出现。

### 19.4 不使用模板化文案

避免：

- 重新定义未来；
- 赋能无限可能；
- 探索 AI 新纪元；
- 智能驱动，创新未来；
- 没有证据的“专家”“全栈”“行业领先”。

### 19.5 不使用模板化布局

避免：

- 居中渐变大标题 + 两个胶囊按钮；
- 三张完全相同的功能卡；
- 巨型聊天框占据首页；
- 满屏技术 Logo；
- 无意义 Bento Grid；
- 所有内容都放进圆角卡片；
- 每个章节都使用同样的居中标题。

### 19.6 不使用廉价游戏化

避免金币、等级、成就、强制控制人物、频繁音效、夸张弹跳和需要学习规则的互动。

### 19.7 不让生成图片承载正式文字

姓名、岗位、项目标题、正文、数据和按钮必须使用真实网页文字。生成素材不带 Logo 和小字，避免错误字符。

## 22. 整站验收标准

### 22.1 信息验收

- 5 秒内识别姓名和岗位；
- 首页可直接查看项目和下载简历；
- 三个核心项目容易比较；
- 项目详情能够看到问题、角色、决策、方案和结果；
- 经历与关于我补充职业可信度；
- 每个页面都能返回、继续浏览或联系；
- 不依赖动画理解内容。

### 22.2 视觉验收

- 所有页面属于同一个低饱和马卡龙像素世界；
- 功能 UI 现代清晰，视觉插画有明确像素感；
- 首页人物与 `avatar-master.png` 一致；
- 标题固定为“贺丹 / AI Product Manager”两行左对齐；
- 三个项目通过主题色和场景区分，但组件系统一致；
- 不出现蓝紫霓虹、玻璃拟态和默认 AI 图标；
- 页面有探索感，同时适合招聘方快速阅读。

### 22.3 交互验收

- 导航、按钮、卡片、章节目录与返回入口可正常操作；
- 页面转场不超过规定时间；
- 快速滚动不会丢失内容；
- 浏览器返回能恢复合理位置；
- 手机端可以正常阅读和点击；
- 减少动态模式下功能完整；
- 无双滚动条与明显布局抖动。

### 22.4 性能验收

- 首屏文字优先出现；
- 图片无明显拉伸与模糊；
- 非首屏素材按需加载；
- 滚动、点击和页面切换无明显卡顿；
- 控制台无持续错误；
- 动效不会影响项目阅读。
