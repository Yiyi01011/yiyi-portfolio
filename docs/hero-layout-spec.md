# 首页 Hero 容器与 P0 素材尺寸规范

> 状态：尺寸确认阶段。本文只定义 Hero 的容器、视觉安全区、分层位置和输出尺寸，不代表正式页面已经实现。  
> 检查原型：`prototypes/hero-asset-layout.html`。  
> 视觉依据：`docs/design.md` 与 `docs/references/homepage-reference-final.png`。

## 1. Hero 整体布局逻辑

Hero 由固定高度导航和一个占满剩余首屏高度的视觉舞台组成。舞台使用真实 DOM 承载标题、价值主张和按钮，透明位图只承担环境层。首屏底部保留项目区衔接层，使用户在不滚动或轻微滚动时感知下一章节。

```text
导航
└─ Hero visual stage
   ├─ CSS 天空背景
   ├─ 远景云 / 中景云
   ├─ 左标题安全区
   ├─ 左环境岛 / 中央人物岛 / 右环境岛
   ├─ 建筑 / 道路 / 植物 / 水流
   ├─ 人物母版
   ├─ 光点
   └─ 前景云与项目区衔接层
```

核心约束：

- 标题安全区永远高于环境图层，人物和浮岛不得进入标题框。
- 人物使用底部中心锚点站在中央岛顶部，人物与中央岛可以组成同一运动组。
- 左右岛是桌面环境平衡层，不是核心信息；平板减少一侧，手机全部隐藏。
- 建筑分别依附左右岛；道路跨岛但只通过透明像素表达连接，不与岛体合成。
- 云层画布横向超出视口，为 12—20px 的运动预留空间。
- 项目衔接层位于 Hero 底部，不遮挡人物脚部和中央岛主体。

```css
--header-height: 72px;

```

平板导航为 64px，手机导航为 56px。不得增加会让首屏产生内部滚动条的固定最小高度。

## 3. 标题、人物和环境的位置关系

### PC：宽度 >= 1200px

- 标题安全区：左侧 `5.5%—46%`，顶部 `9%—50%`。
- 人物：水平中心约 `57%`，人物底部落在舞台高度约 `68%`。
- 中央岛：水平中心约 `57%`，顶部平台与人物脚底重叠 12—20px。
- 左岛：左下，右边缘不得超过舞台宽度 `26%`。
- 右岛：右下，左边缘不得早于舞台宽度 `76%`。
- 三岛主体之间至少保留 4% 舞台宽度；道路透明层可以跨越间隙。
- 项目衔接层占舞台底部约 12%—16%。

### 平板：768—1199px

- 1024 横向仍显示三岛，但建筑缩小，标题宽度不超过 44%。
- 768 竖向保持标题和人物左右错位，中央岛位于人物下方。
- 768 竖向隐藏右岛、右建筑和瀑布；左岛作为远景缩小到舞台宽度约 27%。
- 路径仅显示中央至左侧的有效片段，植物数量减半。

### 手机：< 768px

- 标题区位于顶部，左右各 20px，目标高度 202—214px。
- 人物位于标题与按钮下方，水平居中，完整显示帽子和鞋底。
- 中央岛宽度为可用宽度的 90% 左右，人物脚底与平台顶部重叠 12—16px。
- 左右岛、左右建筑和瀑布隐藏；道路只显示中央短台阶，植物只显示 3—5 个小簇。
- 云层复用桌面素材，通过扩大画布、改变 `object-position` 和裁切适配。
- 同屏只保留云层慢移或人物/中央岛轻浮中的一组持续动画。

## 7. 手机端素材结论

### 直接复用并重排

- `HOM-CLD-001`、`HOM-CLD-002`：扩大画布并裁切。
- `HOM-ISL-001`：缩小并水平居中。
- `HOM-PTH-001`：通过裁切容器只显示中央短台阶。
- `HOM-PLT-001`：通过裁切或对象定位只显示中央小植物簇。

### 手机隐藏

- `HOM-ISL-002`、`HOM-ISL-003`。
- `HOM-BLD-001`、`HOM-BLD-002`。
- `HOM-WTR-001`。

### 是否需要独立手机素材

当前 **不需要独立手机素材**。P0 十项均按可裁切透明母版设计；只有在正式素材生成后发现中央道路或植物无法独立裁切时，才从同一母版导出手机裁切版本，不重新生成第二套画面。

## 8. 图片裁切与溢出规则

- Hero 舞台使用 `overflow: clip`，禁止产生横向滚动条。
- 云层允许画布左右各超出视口 60—125px，为水平运动留出空间。
- 岛、建筑、人物不允许被视口顶部或左右边缘裁切；岛体底部可以被项目衔接层轻微遮住，但主体断面至少保留 80%。
- P0 图层使用明确尺寸和锚点，不使用 `object-fit: cover` 随机裁切。
- 手机路径和植物使用固定裁切窗口与 `object-position`，裁切规则必须可重复。
- 人物始终完整显示，帽顶和鞋底分别保留至少 8px 和 12px 可视空间。
- 标题安全区 z-index 高于全部环境层；环境透明像素不得承载文字可读性。
- 项目衔接层至少保留 24px 垂直运动余量，前景云至少保留 20px 横向或纵向余量。
- 减少动态模式下所有图层回到锚点，不得因为关闭 transform 产生位置跳动。

## 9. 验收标准

- 六个基准视口下标题区与人物、浮岛没有交叠。
- 人物完整可见，中央岛平台与脚底关系稳定。
- 1440、1280、1024 横向显示的三座岛主体不相交。
- 768 竖向隐藏右岛；390 和 375 隐藏两侧岛和建筑。
- 手机 `scrollWidth === innerWidth`，无横向溢出。
- 云层横向画布大于视口，具备最大 20px 位移空间。
- 项目衔接层在 Hero 底部完整可见，并保留 24px 位移空间。
- P0 母版只向下缩放，不在任何基准视口中放大超过源尺寸。
