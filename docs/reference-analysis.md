# Seth Lukin 参考网站分析与使用边界

> 冻结日期：2026-08-15  
> 参考首页：[sethlukin.com](https://sethlukin.com/)  
> 参考案例：[Luuna](https://sethlukin.com/case-studies/luuna)、[Twinby](https://sethlukin.com/case-studies/twinby)、[ADC Space](https://sethlukin.com/case-studies/adc-space)  
> 本文只冻结可借鉴的叙事与动效原则，不将参考站作为视觉复制模板。若发生冲突，以 `docs/design.md` 和 `docs/references/homepage-reference-final.png` 为最高依据。

## 1. 分析范围

本次核对首页、三个公开案例页、现有项目素材与 Hero 分层原型，关注：

- 首页信息进入顺序；
- 从身份介绍到项目的滚动衔接；
- 项目入口的视觉组织与悬停反馈原则；
- 页面进入、退出和案例切换；
- 案例页图文节奏与章节顺序；
- 动效速度、幅度和减少动态策略。

参考站会持续更新，因此不把其运行时代码、字体尺寸或像素坐标作为本项目规范。冻结的是下文明确写出的原则与本项目参数。

## 2. 可借鉴内容

### 2.1 首页进入节奏

参考站先建立姓名、职业与能力方向，再进入个人主张和项目入口。可借鉴的是“先让招聘方知道是谁，再让项目证明能力”的顺序，而不是其姓名排版或首屏版式。

转译到本项目：

1. 导航先可见或快速淡入；
2. “贺丹”与“AI Product Manager”由下向上进入；
3. 价值主张和按钮随后出现；
4. 人物与中央浮岛轻微上浮；
5. 对话框最后出现；
6. 两侧环境只做辅助位移；
7. 0.4 秒内必须出现可阅读文字，总进入时长控制在 1—1.3 秒。

首屏不使用长 Loading、逐字播放整段标题或必须完成操作才能继续的开场。

### 2.2 滚动叙事

参考站通过大标题、项目图像、短文本和留白连续组织页面，项目不是孤立的卡片墙。案例页也保持从命题到证据、再到结果和联系的纵向阅读方向。

转译到本项目：

```text
身份 Hero
→ 项目预览
→ 产品能力与方法
→ 经历
→ 关于我摘要
→ 联系与简历
```

- 保留浏览器自然纵向滚动，不锁定滚轮、不改变滚动方向；
- Hero 底部通过前景云和项目衔接层预告下一章节；
- 每个章节先给结论，再给证明材料；
- 环境图层负责连续性，真实 DOM 负责信息和操作；
- 手机端保持相同叙事顺序，只减少装饰和持续动画。

### 2.3 项目卡出现与悬停

参考站把项目名称、类型和大幅项目图像组织成完整入口，可借鉴“整组出现、图像主导、入口清楚”的方式。不得复制其图片比例、卡片位置、标题形式或素材。

本项目冻结规则：

- 项目卡作为一个整体进入视口，不逐字、逐标签分散播放；
- 进入使用透明度和 12—24px 上移，时长 420—650ms；
- 悬停时封面缩放 1.02—1.04，时长 220—320ms；
- 箭头只移动 4—8px；
- 主题色进入边框或局部背景，文字位置不跳动；
- 整卡可点击，同时保留明确文本链接和键盘焦点；
- 手机没有 hover，改用按下反馈和稳定的文字入口。

### 2.4 页面转场

参考站可借鉴的是“短、连续、沿阅读方向”的转场意识。当前公开页面源码中可见一组约 0.4 秒进入、0.2 秒退出的遮罩配置，但该数值不作为本项目通用参数，也不复制其遮罩形状。

本项目冻结规则：

- 首页到项目详情：项目主题色或封面局部扩展，旧内容淡出并轻微上移，新 Hero 同方向进入；
- 项目之间：从页尾下一个项目入口沿纵向进入；
- 普通页面：保留导航和背景，主内容移动 12—24px；
- 页面转场使用 550—850ms，图片遮罩使用 550—800ms；
- 不使用黑屏、长 Loading、整页旋转或游戏关卡式转场；
- 浏览器返回时恢复滚动位置；
- `prefers-reduced-motion` 下退化为快速淡入淡出。

### 2.5 项目详情页阅读节奏

三个参考案例均以项目命题和项目名开场，随后给出 Overview、Responsibilities，再根据项目展开问题、研究、方案、实现或结果，最后回到联系入口。可借鉴的是章节层级与图文交替，不复制其项目内容和版式。

本项目使用既定产品案例结构：

```text
项目 Hero
→ Overview
→ My Role
→ Challenge
→ Research / Evidence
→ Key Insights
→ Product Strategy
→ Core Flow
→ Solution
→ Implementation
→ Validation
→ Results
→ Reflection
→ Next Project / Contact
```

- 每个章节先说结论，再展开过程；
- 单段正文保持 3—6 行；
- 大图、双列图、流程图和短文本交替；
- 所有图片提供图注，说明它证明什么；
- 真实截图与证据是主角，像素装饰只负责章节衔接；
- 三个项目允许删减不适用章节，但保持“问题—判断—方案—结果”主线。

### 2.6 动效速度与幅度

参考站只用于判断“轻快、连续、不过度停留”的方向。最终数值由本项目 `docs/design.md` 冻结：

| 对象 | 时长 | 位移或缩放 |
|---|---:|---:|
| 按钮与小控件 | 140—220ms | 2—8px |
| 项目卡悬停 | 220—320ms | 1.02—1.04；箭头 4—8px |
| 内容进入 | 420—650ms | 12—32px |
| 大标题进入 | 420—650ms | 20—48px |
| 图片遮罩 | 550—800ms | 由容器裁切，不改变内容顺序 |
| 页面转场 | 550—850ms | 主内容 12—24px |
| 场景视差 | 跟随滚动 | 总位移 8—40px |
| 人物与中央岛待机 | 10—16s 循环 | 垂直 4—6px |
| 云层待机 | 12—20s 循环 | P0 规定范围内最大 16—20px |
| 植物待机 | 8—14s 循环 | 最大 4px 或 2deg |

同一屏幕最多 2—3 组持续动画。动画不能降低项目数据、按钮、导航和正文的可读性。

## 3. 明确不得复制

### 3.1 品牌、文案与项目内容

- 不复制 Seth Lukin 的姓名表现、职业描述、介绍文案、案例标题、联系文案和项目数据；
- 不把参考案例的研究、职责、结果或产品命题改写成本项目内容；
- 本项目所有经历、项目状态、数字和结果必须来自本人确认的真实资料。

### 3.2 图片和具体版式

- 不下载、临摹或改造参考站图片；
- 不复制其首页坐标、项目图比例、章节排列、页尾结构和遮罩形状；
- 不用参考站截图作为网页背景或生成素材输入。

### 3.3 字体组合

- 不复制参考站的字体文件、字重组合、字距和姓名排版；
- 中英文排版继续使用 `docs/design.md` 的字体系统；
- 正式文字始终使用真实 HTML，不生成进位图。

### 3.4 写实视觉风格

- 不采用参考站的写实摄影、人物肖像或黑白高对比方向；
- 不把本项目改成摄影型设计师作品集；
- 不改变低饱和马卡龙二维像素世界，不将人物或环境做成写实、3D、黏土或通用游戏素材。

## 4. 转译到本项目

| 参考层面的启发 | 本项目的原创转译 |
|---|---|
| 强身份首屏 | 左侧真实 HTML 身份文字 + 中央既有人物母版 + 分层浮岛环境 |
| 连续滚动叙事 | 云层、浮岛和项目衔接层连接 Hero、项目、能力与经历 |
| 图像主导项目入口 | 使用四张已确认项目封面，容器和文字由 HTML/CSS 实现 |
| 编辑式案例阅读 | 产品命题、职责、证据、决策、验证、结果的章节结构 |
| 快速页面转场 | 主题色遮罩、轻位移和透明度变化，不复制具体转场造型 |
| 轻量持续动效 | 云、岛和植物的有限视差；不做人物操控或游戏任务 |

PC 端优先建立完整三岛构图；平板减少右侧环境；手机只保留人物、中央岛和必要云层，通过缩放、重排、裁切和隐藏适配，不默认生成第二套手机素材。

## 5. 对 P0 素材拆分的影响

结论：**参考网站不改变现有 P0 拆分。**

原因：

1. 参考站提供的是节奏和案例组织启发，不提供像素世界的素材结构；
2. P0 已按独立运动、锚点、透明边距、手机策略和 z-index 拆成 10 项；
3. 参考站的项目图像展示和页面转场由容器与动效代码处理，不要求把浮岛重新合成；
4. 首页最终参考图明确需要云、三座岛、建筑、道路、植物、水流和人物分层；
5. 合成大图会破坏现有视差、响应式隐藏和透明边缘检查。

P0 继续保持：

- 远景云层；
- 中景云层；
- 中央人物浮岛；
- 左环境岛；
- 右环境岛；
- 左侧遗迹建筑；
- 右侧建筑与电脑台；
- 道路与台阶；
- 首页植物组；
- 瀑布四帧 Sprite。

三座岛仍分别输出透明 PNG，中央岛不含人物，左右岛不含建筑。尺寸、文件名、锚点、安全区域、z-index 和响应式策略全部维持 `docs/hero-layout-spec.md` 与 `docs/visual-assets-plan.md` 的现有结论。

## 6. 冲突裁决顺序

1. `docs/design.md`：整站视觉、信息结构、动效与实现边界；
2. `docs/references/homepage-reference-final.png`：首页配色、像素颗粒、光照、构图与世界观；
3. `docs/hero-layout-spec.md`：P0 尺寸、锚点、安全区、z-index 和响应式；
4. `docs/visual-assets-plan.md` 与 `docs/asset-manifest.md`：素材编号、路径、批次和格式；
5. Seth Lukin 参考网站：只提供进入、滚动、案例阅读和转场节奏启发。

低优先级参考不得推翻高优先级规范。参考站后续变化也不会自动改变本项目已经冻结的 P0 规则。

## 7. 冻结结论

- 参考规则已固定，可进入素材生成前的逐项提示词与验收阶段；
- P0 仍为 10 张，不增、不减、不合并；
- P0-A 三座浮岛无需调整，可以按既定 PNG 文件名、尺寸和安全区分别生成；
- 参考网站不作为 ImageGen 的图像输入，三座浮岛的视觉依据仍是首页最终参考图与本项目已有项目封面。
